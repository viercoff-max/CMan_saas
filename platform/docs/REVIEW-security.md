# Security + privacy review (read-only)

Scope: `platform/` as of 2026-10-05. Reviewer role: Data, Privacy & Compliance Lead.
Assumptions: (A1) the first deployment is on-prem using `npm run dev`, as ARCHITECTURE.md says, with a public tunnel (ngrok/cloudflared) for Meta and Shopify callbacks. (A2) There is a single tenant today (`chefman`), and brands #2 and #3 will follow on the same instance. (A3) `.env.local` reflects the deployed config (`META_APP_SECRET` is empty).

Things that are done well and need no change: every SQL query in `store.ts` and the module repos is scoped by `tenant_id`. Route handlers take the tenant from the session, never from the body, so there is no cross-tenant IDOR today. All SQL is parameterized. React output is escaped, and nothing uses `dangerouslySetInnerHTML`. Secrets are AES-256-GCM encrypted with a fresh IV. Shopify OAuth uses a signed, expiring state cookie, compares the state in constant time, validates the HMAC and restricts the shop domain to `*.myshopify.com`. `fetch-safe` pins DNS at connect time, re-validates every redirect, and handles decimal/octal/hex IPv4 (the WHATWG URL parser normalizes them), IPv4-mapped IPv6 and NAT64. The upload route defeats path traversal. Logs carry no tokens, message text or emails. Email is held only transiently in the order flow and never reaches the LLM.

## Before production checklist

**Security (blocking)**
- [ ] C1: webhook signature always enforced; `META_APP_SECRET` set; startup fails without it.
- [ ] H2: run `next build && next start`; tunnel exposes only `/api/webhooks/meta` and `/api/shopify/callback` (and the data-deletion callback); admin UI on localhost/VPN only; `Secure` + `__Host-` cookies.
- [ ] H3: `DATA_DIR` and secrets moved out of OneDrive to an ACL'd, BitLocker-protected path; `ADMIN_PASSWORD` removed after seed; secrets rotated (they have already been in a synced folder).
- [ ] H1 + M1: cross-conversation lookup limiter (hashed keys) and identical not-found/mismatch responses, with tests.
- [ ] M2/M3/M6: Origin check in `proxy.ts`, login rate limit with async scrypt, per-sender inbound throttle and LLM budget.
- [ ] Daily backups of `app.db` (encrypted) with a tested restore.

**LFPDPPP (new law, DOF 20-Mar-2025; authority now the Secretaría Anticorrupción y Buen Gobierno)**
- [ ] **Aviso de privacidad integral** published by Chefman (the *responsable*): identity and address, purposes (primary: support and order status; secondary: cross-sell, which needs an opt-out mechanism), data categories, **remisiones** to processors (Momentia, OpenAI, hosting), transfers, ARCO and consent-revocation mechanism, how changes are communicated.
- [ ] **Aviso simplificado in channel**: the first bot message (greeting) includes one line plus a link to the full notice before collecting order number or email. Tacit consent is enough for ordinary data. Safety and injury reports are **sensitive (health) data**: minimize them, keep them out of the LLM (M5), and restrict access.
- [ ] **Contrato de encargo / DPA** between Chefman (responsable) and Momentia (encargado): instructions, confidentiality, security measures, sub-processors (OpenAI with a DPA and ZDR, cloud or on-prem host), breach notification, return or deletion at contract end.
- [ ] ARCO procedure: a contact email and a response within the legal deadline (20 business days), backed by the `deleteCustomer` / `redactByEmail` functions (H4).
- [ ] Security measures documented (access control, encryption, backups, logging), plus a breach-response runbook that notifies affected titulares without delay.
- [ ] **Retention policy and purge job**: conversations and messages retained ≥30 days (configurable per tenant, e.g. 90), then deleted or anonymized; outbox files ≤30 days; legal hold for safety and legal escalations (product-liability and PROFECO exposure); purge results audit-logged (counts only).

**Meta platform**
- [ ] App Review for `pages_messaging`, `instagram_manage_messages` (and `whatsapp_business_messaging` if used), with Business Verification. Request `Human Agent` only if L5 is implemented.
- [ ] Privacy Policy URL and **Data Deletion Callback** (`/api/meta/data-deletion`): verify the `signed_request` HMAC-SHA256 with the app secret, delete or anonymize that user's conversations and messages, return `{url, confirmation_code}`, and offer a status page. Optionally add a deauthorize callback.
- [ ] Respect the 24 h window (L5). Disclose that the customer is talking to an automated assistant, with a clear path to a human (already handled by the escalation rules). WhatsApp: opt-in and escalation path, and the bot stays limited to business customer support (no general-purpose AI assistant).
- [ ] Do not use Platform Data for anything beyond support (no cross-sell profiling from message content outside the conversation). Complete the annual Data Use Checkup.

**Shopify**
- [ ] Protected Customer Data access request (email = level 2) for the app. Without it, `email` is null and every lookup fails generically.
- [ ] Mandatory compliance webhooks `customers/data_request`, `customers/redact`, `shop/redact` (HMAC-verified), wired to `redactByEmail` / tenant wipe. `read_all_orders` only if approved.
- [ ] On disconnect or uninstall (`app/uninstalled` webhook), wipe the stored token.

**Multi-brand readiness (before brand #2)**
- [ ] M7: verified, unique channel ownership. Roles (L6). Per-tenant retention and privacy-notice URL in settings. Postgres + RLS as planned.

## Fix status: FIXER-B (platform security + data lifecycle), 2026-10-05

- **M3 login**: async `scrypt` (`util.promisify`); dummy scrypt for unknown users and locked accounts (no timing enumeration); limits 5 failures per email and 10 per IP in 15 min (table `login_attempts`, HMAC-hashed keys, lazily created in `src/lib/security/rate-limit.ts`); one generic error and the same `{ok}` shape for wrong email, wrong password and lockout; audit rows `auth.login_ok|login_failed|login_locked` with hashed IP only. `npm run set-password` rotates a password without writing it to disk.
- **H2 (partial)**: session and Shopify state cookies are `Secure` whenever `PUBLIC_URL` is https (not only `NODE_ENV=production`); `npm run start:prod` (`next build && next start -H 127.0.0.1`); `docs/RUNBOOK.md` documents the tunnel path allow-list. `__Host-` prefix not adopted (would log everyone out; low value once the admin UI is localhost-only).
- **M2**: `src/lib/security/origin.ts` `assertSameOrigin`/`checkSameOrigin` applied to all state-changing routes under `api/shopify` (connect, manual, test, demo, disconnect) and `api/sources/upload`. The OAuth callback GET is excluded (signed state + HMAC). Inbox routes: requested in REQUESTS.md. Server Actions: Next compares `Origin` with `Host`/`X-Forwarded-Host` and rejects mismatches (`node_modules/next/dist/docs/01-app/02-guides/server-actions.md`, "CSRF check"); note that a request with **no** Origin header is let through with a warning (`03-api-reference/05-config/01-next-config-js/serverActions.md`), which browsers do not produce for cross-site POSTs, so SameSite=Lax + this check is adequate.
- **H4**: `src/lib/retention/index.ts` `purgeOldData`, `deleteCustomerData`, `exportCustomerData`; CLI `npm run purge`, `npm run delete-customer`; daily schedule in RUNBOOK. Legal hold = escalation `safety`/`legal` (or `state.legalHold`), masked after 365 days. Meta data-deletion: `src/lib/retention/meta-deletion.ts` (route owned by inbox). Shopify `customers/redact` wiring still open (needs an email to conversation mapping; emails are now masked in message bodies, so redaction by email has little to find).
- **H3 (operational)**: `DATA_DIR` documented in `.env.example`/setup, setup warns when run inside OneDrive, seed warns while `ADMIN_PASSWORD` is still set; RUNBOOK section 1 covers moving data and rotating secrets.
- **M7 (partial)**: partial unique index `uq_channel_external` (db.ts). Graph ownership check is the channels module's.
- **L1**: fetch-safe blocks `fec0::/10`, Teredo `2001::/32`, `64:ff9b:1::/48`; ports limited to default/80/443/8080/8443.
- **L2 (partial)**: upload requires multipart + Content-Length (no chunked bodies), MIME-vs-extension allowlist and magic bytes (`%PDF-`, `PK\x03\x04`, no NUL in text), 30 uploads/hour per tenant. Parsing in a worker with limits is still open.
- **Rate limits**: Shopify connect/manual 10 per 15 min, test 20 per 10 min, per tenant.
- **DB**: indexes `messages(tenant_id, conversation_id, created_at)`, `messages(tenant_id, created_at)`, `messages(tenant_id, providerMessageId)`, `conversations(tenant_id, last_message_at)`, `audit_log(tenant_id, created_at)`; `busy_timeout=5000`.
- Tests: `src/lib/security/__tests__/security.test.ts`, `src/lib/retention/__tests__/retention.test.ts` (temp DATA_DIR).
